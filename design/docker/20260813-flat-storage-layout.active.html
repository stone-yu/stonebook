拆分并扁平化持久化目录

将应用状态、导入源、Calibre 正式书库和有声书资产拆成四个顶级挂载，消除 /data/books 的混合职责，并明确拒绝旧布局。

状态：ACTIVE创建日期：2026-08-13所属模块：docker影响范围：docker / webserver / tests / document需求来源：当前 Codex 对话

1. 原始诉求

“把目录改一下吧，/data 下面只放 db config 等信息，/imports 作为本地文件扫描来源，/library 作为刮削后的数据。”后续确认采用扁平结构、独立 /audiobooks、持久化 /data/work、可写 /imports，并选择直接破坏性切换。

2. 目标与边界

目标

  • /data 只承载应用数据库、配置、日志、进度与工作状态。
  • /imports、/library、/audiobooks 独立挂载。
  • Calibre 配置显式落到 /data/calibre，不再使用 /root/.config/calibre。
  • 旧布局必须先人工迁移，启动不得静默创建空书库。

非目标

  • 不自动移动、复制或删除旧部署数据。
  • 不保留旧路径回退。
  • 不改变 Calibre 管理书籍文件的方式。
  • 不改变 API 与前端业务交互。

4. Compose 与启动流程

volumes:
  - "${TALEBOOK_DATA_DIR:-./data}:/data"
  - "${TALEBOOK_IMPORTS_DIR:-./imports}:/imports"
  - "${TALEBOOK_LIBRARY_DIR:-./library}:/library"
  - "${TALEBOOK_AUDIOBOOKS_DIR:-./audiobooks}:/audiobooks"
  1. 创建并检查四个挂载点。
  2. 在预置数据初始化前检测 /data/books 的真实旧数据。
  3. 命中旧布局时 bootstrap 失败，Nginx 与状态页继续服务并展示迁移目标。
  4. 新布局中只初始化缺失的业务库、配置和 Calibre 书库，不覆盖已有数据。
  5. 分别报告四个目录的权限问题；显式只读的 imports 可启动，但不能删除源文件。

/root/.config/calibre 不自动迁移；若管理员确有自定义 Calibre 配置，需审查后人工复制到 /data/calibre。

6. 风险与回滚

  • 破坏性升级：旧 Compose 不能直接启动新版；通过启动前检测防止误初始化。
  • 跨挂载原子性：应用不得假设四个挂载之间支持原子 rename；每类资产只在自身根目录内提交。
  • 权限：library、audiobooks 与 data 必须可写；imports 只读时删除源文件操作应给出明确错误。
  • 回滚：停服后恢复旧镜像和旧 Compose，并保持旧目录原状；新版不自动改写旧布局。
