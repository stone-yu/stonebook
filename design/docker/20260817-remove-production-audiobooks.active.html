生产镜像移除有声书能力

缩小默认 SPA 镜像，并让 Compose 的持久化目录重新聚焦应用状态、扫描来源和正式书库。

状态：ACTIVE创建日期：2026-08-17所属模块：docker影响范围：镜像、Compose、启动自检、部署文档需求来源：用户原话

1. 原始诉求

“1.移除生产镜像中的 ffmpeg 和 voicebook-tool；2.提供的docker compose yml 也删除有声书相关的内容”

2. 目标与边界

  • 默认生产镜像不安装 FFmpeg 和 voicebook-tool。
  • 生产镜像、启动自检和 Compose 不再创建、声明或要求 /audiobooks。
  • 默认关闭有声书 API 与后台调度，关闭状态下不得创建存储目录。
  • 保留已有业务代码、表结构及旧布局识别，便于未来重新设计和避免旧数据被误初始化。

3. 方案比较与选择

方案结果
只删 Compose 挂载镜像不变，调度器仍可能写 /audiobooks，不采用。
只删二进制依赖镜像变小，但界面/API 可能暴露不可用能力，不采用。
依赖、运行契约与默认开关一起下线镜像与部署契约一致；保留代码以便未来恢复，采用。

4. 实现方案

  1. 删除 Dockerfile 中 FFmpeg 安装、生产目录及卷声明，删除 Python 依赖中的 voicebook-tool。
  2. Compose 只挂载 /data、/imports、/library。
  3. 生产启动脚本和自检只检查三类运行根；旧 /data/books/audiobooks 仍用于识别待人工迁移的旧布局。
  4. 默认关闭有声书功能和 runner，并让 scheduler 在禁用检查后才初始化存储。
  5. 同步中英文部署文档与静态契约测试。

5. 风险与兼容性

已有宿主机 audiobooks/ 不会被删除，只是不再挂载。直接调用旧有声书接口将得到禁用结果。未来恢复时应重新评估独立 worker 或可选镜像，而不是重新放回默认 SPA 镜像。
