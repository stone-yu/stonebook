GHCR SPA 镜像发布

以 fork 仓库自身的 Git tag 为发布入口，替换原 Docker Hub 多变体流程。

创建日期 2026-08-14模块 project状态 ACTIVE来源：用户连续需求

原始诉求

参考 stone-yu/music-hub 的 docker-image.yml，为当前 fork 实现 GitHub Workflow 自动生成 Docker 镜像；直接替换现有 Docker Hub 构建，并且只发布默认 SPA 镜像。

目标与边界

  • 推送任意 Git tag 时发布 ghcr.io/<owner>/<repo>。
  • 发布 tag 同名版本和滚动的 latest 标签。
  • 只构建 Dockerfile 的 production-spa target，平台为 amd64 与 arm64。
  • 不再发布 SSR、dev、ARMv7 镜像，不再依赖 Docker Hub 用户名与密码。
  • 分支 push 与 pull request 不触发本发布 workflow；普通 CI 仍由独立 workflow 承担。

方案

Tag push任意 tag 触发
GHCR 登录actor 与 GITHUB_TOKEN
Buildx 构建production-spa 双架构
发布tag 与 latest

Workflow 使用最小权限 contents: read 与 packages: write。镜像版本通过 GIT_VERSION build argument 传入应用，元数据 action 统一生成 OCI 标签和 labels，GHA cache 加速后续构建。

影响与风险

项目变化处置
镜像地址Docker Hub 改为 GHCR用户需改用 ghcr.io/<owner>/<repo>
兼容性停止 SSR、dev、ARMv7 发布符合本次只发布默认 SPA 的边界
包可见性首次创建的 GHCR package 可能受仓库/组织设置影响发布后在 GitHub Packages 中确认所需可见性
本地验证登录与真实推送无法安全模拟使用 act 验证可复现步骤，真实 tag 验证外部边界
