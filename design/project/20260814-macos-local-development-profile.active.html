macOS 本地开发 Profile

不依赖 Docker，复用 Calibre.app 的嵌入式 Python 和仓库虚拟环境依赖。

创建日期 2026-08-14模块 project状态 ACTIVE来源：用户需求

原始诉求

增加一套完整 macOS 本地启动 profile：自动处理本地目录、Calibre.app 检测、Python 依赖桥接、数据库和书库初始化，并提供稳定的一键开发入口。

目标与边界

  • 生产默认配置继续使用容器内的四个顶级挂载，不因 local profile 改变。
  • TALEBOOK_PROFILE=local 时使用仓库根目录下的 data、imports、library、audiobooks。
  • 后端通过 Calibre 官方支持的 calibre-debug -e 运行，从而获得可导入的 Calibre 模块。
  • 仓库 .venv 的第三方依赖显式加入嵌入式 Python 的模块搜索路径。
  • 不自动安装 Calibre、Node 或 Python 包，不修改用户的 Calibre 全局配置。

方案

检查Calibre.app 与 .venv
准备创建本地四目录
初始化metadata.db 与应用 DB
运行calibre-debug 启动 Tornado

配置加载顺序调整为“生产默认值 → 可选 profile → profile 的 settings 目录内 auto.py → manual.py”。启动器支持 PATH 中的 Calibre，也支持 macOS 标准应用目录，并允许用 TALEBOOK_CALIBRE_BIN_DIR 覆盖。初始化操作只在数据库不存在时执行，避免覆盖已有书库。

接口与错误处理

入口行为失败提示
make dev-local-check只检查环境并准备目录给出 Calibre 安装或 .venv 初始化命令
make dev-local必要时初始化并启动 8080 后端保留子进程退出码和原始异常
make dev-ui-local启动连接 8080 的 Nuxt由 Nuxt 输出依赖或端口错误
