书架分类批量移出书架

在书架页分类树每个（子）分类节点旁增加"移出书架"操作，按当前 recursive 开关把该分类下的书籍批量取消收藏（移出书架），作为现有"加入书架"批量接口的反向镜像。

状态：ACTIVE 创建日期：2026-08-19 所属模块：app 影响范围：书架页、分类树组件、书架分类接口、书架分类服务 需求来源：用户原话

1. 原始诉求

”书架里面 可以在分类后面增加移出书架的功能，把选择子分类的书籍 批量移出书架。”

触发背景：书架页（app/pages/user/shelf.vue）已按个人书架分类（ShelfCategory/ShelfCategoryBook）组织书籍，并已有逐节点”加入书架”按钮与批量”加入书架”接口（POST /api/categories/{id}/shelf → add_books_to_shelf）。但缺少反向的”按分类批量移出书架”，且书架页目前没有逐本移出按钮，用户想把某子分类下的书整体移出书架时只能逐本去书详情页取消收藏。

2. 目标与边界

目标

  • 新增后端服务 remove_books_from_shelf(session, reader_id, book_ids)：对每本书 set_wants(False) 取消收藏并清理其全部 ShelfCategoryBook 链接，返回 {total, removed, skipped}，签名与返回结构镜像 add_books_to_shelf。
  • 新增端点 POST /api/shelf/categories/{id}/remove，@js @auth，按 recursive 解析该书架分类的书籍并调用上述服务；校验分类属于当前用户。
  • CategoryTreePanel 增加逐节点"移出书架"按钮（新 removable 属性，count>0 且 hover 显示），emit remove-from-shelf。
  • shelf.vue 处理 remove-from-shelf：弹确认框→调用端点→刷新树与列表；i18n 补 zh-CN/en-US。
  • 不变量：只操作当前用户自己的书架分类与 ReadingState；recursive 行为与列表展示一致；移出只取消收藏（wants=0），不删阅读进度与标注。

非目标

  • 不做逐本移出书架（单本路径 book.py:2317 已有，本次不重复）。
  • 不改图书馆分类（LibraryCategory）与 admin 分类管理。
  • 不改"加入书架"接口与按钮。
  • 后续：可在书架页加逐本移出按钮（本次不做，触发条件为用户再次提出）。

3. 方案

方案结论：反向镜像"加入书架"。后端新增 remove_books_from_shelf 服务（镜像 add_books_to_shelf 的去重/计数与返回结构）与 ShelfCategoryRemove 端点（镜像 LibraryCategoryShelf 路由风格，作用域为个人书架分类 ShelfCategory）；前端在 CategoryTreePanel 逐节点加"移出书架"按钮（镜像现有"加入书架"按钮），shelf.vue 加确认框与调用。所有权在书架分类服务层，数据流：节点 → 端点 → category_book_ids 解析 → remove_books_from_shelf 改 ReadingState.wants 与 ShelfCategoryBook。
Input点击"移出书架"

书架页分类树某（子）分类节点 append 按钮触发 remove-from-shelf 事件。

Guard鉴权与归属

@auth 登录校验；端点校验 ShelfCategory 存在且 reader_id 等于当前用户，否则 category.not_found；recursive 取页面开关。

Core批量取消收藏

category_book_ids(session, ShelfCategory, id, recursive, reader_id) 解析书籍；对每本 set_wants(False) 并 remove_book_from_shelf_categories（清全部 ShelfCategoryBook 链接）。

Output计数与刷新

返回 {err:ok, total, removed, skipped}；前端 toast 显示 removed 数量并刷新树与列表；失败返回 err+msg。

关键决策

决策点选择理由放弃项
移出语义彻底移出书架（set_wants(False)+清全部链接）用户原话"移出书架"；与单本移出 book.py:2317 一致；保留阅读进度与标注仅移出该分类（删单条链接）——一书多分类时语义混乱
递归范围沿用页面 recursive 开关与列表展示范围一致，所见即所移固定递归/不递归——与展示不一致易误删
确认 UX弹框二次确认（分类名+含子分类提示）批量不可逆操作直接执行——误操作风险高
按钮位置节点 append（镜像加入书架，count 大于 0 才显示）"在分类后面"；与现有范式一致底部操作栏——需先选中，多一步
端点形状独立路由 POST /api/shelf/categories/{id}/remove镜像 LibraryCategoryShelf 的 /api/categories/{id}/shelf作为 ShelfCategoryTree 的 action——该 handler 走单本 book_id 语义，不匹配批量

4. 影响范围、风险与回滚

影响范围

新增服务函数与端点（webserver/services/categories.py、webserver/handlers/categories.py 的 ShelfCategoryRemove 与 routes()）；前端组件、页面、i18n、图标（app/components/CategoryTreePanel.vue、app/pages/user/shelf.vue、app/i18n/locales/*.json、app/utils/local-mdi-icons.ts）；测试（tests/test_categories.py、app/test/components/）。权限：仅当前用户操作自己的书架分类。

保持不变

加入书架接口与按钮、图书馆分类与 admin 分类管理、ReadingState 的阅读进度字段、标注数据、书架分类树 CRUD 均不变。

主要风险：误删（一书同属多个书架分类时整本离开书架）→ 触发：用户对含子分类的分类点移出 → 缓解：确认框显示分类名与”含子分类”提示，执行后 toast 显示实际 removed 数量；权限越权 → 端点校验 reader_id，测试覆盖非 owner 返回 not_found。
回滚：代码层回滚（删除端点、服务、按钮即可，无数据迁移）；已被移出的书需用户重新”加入书架”恢复（set_wants(True)），不影响阅读进度。

6. 决策记录

  1. 2026-08-19：grill 四项默认（移出语义=彻底移出书架、递归=沿用页面开关、确认=弹框、按钮=节点旁）由方案提出，用户回复"确认"采纳。
  2. 2026-08-19：端点用独立路由而非 ShelfCategoryTree 的 action，因该 handler 走单本 book_id 语义，不匹配批量。
  3. 2026-08-19：移出按钮复用现有 add-to-shelf 的 hover/计数范式，新增 removable 属性区分页面，避免污染 categories.vue 与 admin/books。
  4. 2026-08-19：CI 验证通过（test-server pytest 877 passed 含 TestShelfCategoryRemove 2/2；test-ui lint+build 通过），方案由 WIP 转 ACTIVE。实际渲染受本机无 Docker 限制，以组件测试 + Nuxt build 替代。
