找书入口重组与分类管理集中化

把分类导览、本地书库、网络书库三个入口提到找书页最顶部；让分类导览页回归纯浏览；把分类筛选与分类 CRUD 集中到图书管理页，并将批量封面从逐本设置改为统一一张封面应用到全部选中书。

状态：ACTIVE 创建日期：2026-08-18 所属模块：app 影响范围：app/pages、app/components、app/utils、app/i18n、webserver/handlers、tests 需求来源：用户原话 + grill 澄清

1. 原始诉求

  1. 找书下面的分类导览，和本地书库、网络书库三个网格放到找书页面顶部。
  2. 找书的分类导览页面，左侧分类不可编辑。
  3. 图书管理增加分类筛选，方便基于分类进行批量管理；批量修改封面不是每本单独设置封面，而是选中的图书统一改成一张封面。

grill 澄清结论：① 三网格置于 /discover 最顶部（hero 下移）；② 分类 CRUD 从 /categories 迁移到图书管理页展示，浏览页纯只读；③ 按分类批量仅当前页全选，不做跨页整类全选；④ 统一封面来源为单文件上传。

2. 目标

  • /discover 首屏即分类导览/本地书库/网络书库三个入口卡片，搜索框下移但仍可用。
  • /categories 成为纯浏览页：左侧分类树与单本归类操作全部只读。
  • /admin/books 承接分类筛选、分类 CRUD 管理与统一批量封面，成为分类相关操作的唯一管理入口。

3. 方案

3.1 找书页入口重组（app/pages/discover.vue）

原结构：hero（标题+搜索框）→ source-grid（本地/网络 2 卡）→ filter-grid（9 项，分类导览是其中之一）。

改造后顺序：entry-grid（3 卡）→ hero（标题+搜索）→ filter-grid（8 项）。

  • 新增顶部 entry-grid：分类导览→/categories（mdi-widgets）、本地书库→/library（mdi-bookshelf）、网络书库→/network（mdi-cloud-search，受 store.sys.show_network_library !== false 控制隐藏）。
  • 将原 source-grid 的本地/网络两卡并入 entry-grid；从 filter-grid 移除分类导览项（剩作者/出版社/标签/文件格式/丛书/评分/热门/最近 8 项）。
  • hero 下移到 entry-grid 之下，discover.subtitle 改写避免与三卡文案重复；新增 discover.categoryDescription 作为分类导览卡片描述。
  • 响应式：3 列桌面 / 2 列平板 / 1 列移动；同时把原先未注册的 mdi-cloud-search-outline/mdi-tag-outline/mdi-file-outline 换为已注册的 mdi-cloud-search/mdi-tag/mdi-file。

3.2 分类导览页改只读（app/pages/categories.vue）

  • :manageable 由 Boolean(store.user.is_admin) 改为 false，隐藏左侧"新增一级分类"与新增子分类/重命名/移动/合并/删除工具条及对应对话框。
  • 移除右侧每本"调整分类"按钮及其 moveBook 对话框，使整页纯浏览；删除随之无用的 editBook/saveBookCategory/operate/categoryOptions 等状态与函数。
  • 保留加入书架（shelfable）等用户侧能力；CategoryTreePanel.vue 组件本身不改。

3.3 图书管理分类筛选 + 分类 CRUD（app/pages/admin/books.vue + webserver/handlers/admin.py）

  • 工具条新增"分类管理"按钮（mdi-widgets）打开分类管理对话框，内嵌 CategoryTreePanel（:manageable="true"）：选择分类即设置筛选并刷新表格；CRUD 工具条走 POST /api/admin/categories，完成后刷新分类树。
  • 工具条同步新增分类筛选 v-select（扁平化分类树，带缩进）+"包含子分类"开关，与对话框选择联动；当前所选分类以 chip/可清除展示。
  • 表格新增"分类"列（取 GET /api/categories 的 book_categories 映射），单元格可点击打开单本"调整分类"对话框，承接从 /categories 迁来的单本归类能力。
  • 后端 AdminBookList.get 新增 category_id、recursive 查询参数：存在 category_id 时，用 webserver.services.categories.category_book_ids(...) 取该分类书 ID 集合与 all_ids 取交集；category_id=0 表示未分类（排除已分配书）；无 category_id 时行为完全不变。

3.4 统一批量封面（app/pages/admin/books.vue + app/utils/batch-covers.ts）

  • 批量封面对话框：移除逐本 v-file-input 列表，改为单个 v-file-input + 进度条；batchCoverSubtitle 改为"选择一张封面，应用到全部选中的 {count} 本书"。
  • 新增工具函数 uploadOneCoverToBooks(file, bookIds, backend, onProgress)：循环将同一 file 以 cover 字段 POST 到 /book/{id}/edit，复用现有 BookEdit.upload_cover 校验与写入；单本失败不阻断，汇总成功与失败。删除原逐本 uploadBookCovers。
  • 后端 POST /api/book/{id}/edit → BookEdit.upload_cover 无需改动。

3.5 图标注册（app/utils/local-mdi-icons.ts）

新增 6 个本地图标以让复用的 CategoryTreePanel CRUD 与找书评分入口正常渲染：mdi-call-merge、mdi-folder-move、mdi-folder-outline、mdi-folder-plus、mdi-folder-question、mdi-star-outline。

4. 数据与接口

能力接口说明
分类树与映射GET /api/categories返回 tree 与 book_categories（book_id→category_id），用于筛选 v-select 与表格分类列。
分类 CRUDPOST /api/admin/categoriesaction=create/update/merge/delete/assign/unassign，对话框工具条复用。
带分类筛选的书目列表GET /api/admin/book/list新增 category_id、recursive 参数；其余参数与分页/排序不变。
单本/统一封面POST /api/book/{id}/editmultipart 字段 cover；统一封面循环复用同一文件，后端不改。

6. 影响范围与关联

  • 影响：app/pages/discover.vue、app/pages/categories.vue、app/pages/admin/books.vue、app/utils/batch-covers.ts、app/utils/local-mdi-icons.ts、app/i18n/locales/zh-CN.json 与 en-US.json、webserver/handlers/admin.py、tests/test_admin.py、app/test/utils/batch-covers.spec.ts。CategoryTreePanel.vue 仅调用方改，组件本身不变。
  • 关联：本方案细化 design/app/20260818-library-batch-management.active.html 的"批量封面"口径（由逐本改为统一一张应用到全部选中书）；其"分类批量入架"与"默认排序"不变。该关联已在正文 3.4 注明。
  • 关联：design/app/20260817-unified-facet-book-browsing.active.html 的双栏布局仍由 /categories 等维度页沿用，本方案不改其布局，仅切换 manageable。

7. 风险与边界

  • /categories 移除 CRUD 后，管理员分类管理唯一入口迁至 /admin/books 对话框；需保证对话框对所有管理员可见且 CRUD 可达（由 CategoryTreePanel :manageable="true" 与 POST /api/admin/categories 的 @is_admin 保证）。
  • AdminBookList 增参必须保持无 category_id 时行为不变（向后兼容），并沿用现有管理员校验；已由 if category_id != "" 分支保证。
  • 统一封面循环上传对大量选中书耗时，须有进度条与失败汇总，且单本失败不阻断其余（已实现）。
  • 批量按分类仅当前页全选：大分类需逐页操作，已在 grill 中确认为可接受。
  • 后端分类筛选与浏览器验收受环境限制未实跑，见第 5 节风险条。
